# ETAutomationsAPI — browser-free rebuild spec for ETAutomations

This repository contains **implementation notes** (a complete specification) for rebuilding the
[ETAutomations](https://github.com/Koilparampil/ETAutomations) ETA-tracking and invoice pipeline **without
Playwright or any browser automation**, using direct API calls instead. The notes are written so that you can
hand them to Claude and get back a complete, tested Python program.

## Is it possible? Yes.

| Part of the pipeline | Today | In the rebuilt program |
|---|---|---|
| QuickBooks: ETA field, invoice number, e-mail | Drives the QuickBooks web app in Chromium | QuickBooks Online Accounting API (OAuth you already have) |
| MSC ETA | Headless browser login + a new browser per booking | MSC's official DCSA Track & Trace API (after onboarding); meanwhile the same GraphQL query over plain HTTP with a token you paste from your own browser |
| Maersk ETA | Visible Chrome per booking (Akamai) | Maersk's official "Track & Trace Events" API on your existing developer app |
| CMA CGM ETA | Visible Chrome per booking (DataDome, sometimes a CAPTCHA) | CMA CGM's official tracking API (API key) |
| VShipCRM | Already HTTP | Same API, async and cached |

**Speed:** a ~500-row file that takes several hours today should take roughly 10–20 minutes (estimate):
all lookups run concurrently, each step is one HTTP call instead of a page load, and nothing waits on
browser warm-ups, pop-ups or `slow_mo`.

**Safety:** the new program plans first and changes nothing until you confirm (or use `--dry-run`). It never
retries an e-mail that may have been sent, keeps a same-day ledger against duplicates, and refuses to e-mail
customers until a one-time test send to your own inbox proves the subject line comes through correctly.

**What needs your action before it can run live** (details in `spec/13-rollout-checklist.md`):
- **Maersk:** approval of the "Track & Trace Events" API product.
- **CMA CGM:** an API Portal registration (30-day free trial, then a contract).
- **MSC:** an Integration Form request for official API access. Until then, paste a browser token each run.
- **QuickBooks:** a redirect URI, the ETA field enabled for invoices, and a test customer.

## How to use these notes

See `BUILD_PROMPT.md`. In short: open this repository in **Claude Code** and paste the prompt. Claude reads
`spec/`, writes the program into `src/` and `tests/`, and runs the tests until they pass. Then follow
`spec/13-rollout-checklist.md`.

After editing anything in `spec/`, regenerate the single-file bundle with `python tools/bundle_spec.py`.

## Verification status

Facts were taken from official documentation where available and checked with unauthenticated requests on
2026-11-05. Every spec ends with a **Sources & verification status** table. The items that cannot be confirmed
without your credentials have a probe command that checks them on first run. The most important are:

1. whether QuickBooks' API writes the ETA **date** custom field (`eta probe qbo --write-test`);
2. whether the template-swap e-mail arrives with the exact subject (`eta probe qbo --send-test`);
3. whether MSC's official API accepts `EBKG…` booking numbers (`eta probe msc --compare`);
4. whether the Maersk "Arrives" date matches the API's final-destination arrival or the port-of-discharge arrival (`eta probe maersk`).
